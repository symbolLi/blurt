# lens: pm — PM 录屏口述的产品 bug 反馈（导出飞书多维表格）

Use for: 用户（PM）对着产品录屏口述 bug / 体验问题时使用。一段录音里通常有多个问题，一个问题一条
item；用户说"不对，是…"以更正后的为准。不要自动套用 issue lens 的 `code_refs` / `owner`，除非确实
在代码项目里录制。

Fields:
- `module` — 所属模块：用户口述的模块名，或界面上的导航/页面名。
- `summary` — 一句话详细描述，导出飞书"详细描述"列直接用：`{模块}。{现象}；预期 {预期}`，保留全部数字事实
  （金额、耗时、次数），不贴原话、不复述复现步骤。导出只搬运这个字段，不在导出时生成文本。
- `severity` — `high`（阻断 / 结果错误）· `medium`（明显影响体验）· `low`（外观 / 文案）。导出映射 高/中/低。
- `type` — 直接用飞书表格的问题类型选项值：`功能异常` · `计算错误` · `性能问题` · `UI 文案` · `其他`。导出时原样写入。
- `expected` / `actual` — 预期 vs 实际。涉及数字必须带数字（金额、耗时、次数、版本）。不确定写进
  `questions`，不要编。
- `steps` — 复现步骤（编号列表）。
- `quote` — 用户原话，逐字保留，不改写。
- `source.app` — 被反馈的产品名（用户提到或屏幕可见）。
- 每条 item 必须有 `title`（一句话问题描述，直接当飞书"问题描述"列）和 `tags`。

Frames: 每个问题至少一张标注帧——box 圈住出错的具体位置（数字、按钮、文案），不要无标注的整页截图；
跨屏操作可用多张帧。所有帧在导出时全部作为附件上传（附件格支持多图）。

Export default: 飞书多维表格「Bug 反馈清单」。绑定与导出都不经过 Agent：用户在 Blurt 客户端
「设置 → 飞书」里填自建应用的 App Key / App Secret / 表格链接完成绑定，然后在主窗口列表里勾选、
右键「导出到飞书」（feishu_export.py 直连飞书 OpenAPI 写入）。列映射（列名可在 config
export.feishu.columns 覆盖）：

| 飞书列 | 来源 |
|---|---|
| 问题描述 | item `title` |
| 详细描述 | item `summary`（生成时写好；老条目缺失时导出按 `{module}。{actual}；预期 {expected}` 兜底拼接） |
| 评论 / 链接 / 跟进人 | 留空（评论列给开发用） |
| 状态 | 固定 `待处理` |
| 严重程度 | `severity` 映射：high→高 · medium→中 · low→低 |
| 问题类型 | `type` 原样 |
| 提出人 | 绑定时填的名字（飞书里按名字精确匹配到人） |
| 提出时间 | item `created` |
| 截图 | 全部 frames 逐张上传，文件名 `<id>-<n>-<caption>.jpg` |

预期效果 / 实际效果 / 复现步骤 / 原话这些详细字段只留在 Blurt 条目里，不进表格——开发从"问题描述 +
详细描述 + 截图"就能知道发生了什么，需要细节再看条目。
